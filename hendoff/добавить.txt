--- НОВЫЕ ФУНКЦИИ (появились в adb_tools.py) ---

grab_screen()
    Скриншот -> BGR numpy-массив, без файла на диске.
    ДВА ВАРИАНТА РЕАЛИЗАЦИИ:
      A) raw: adb exec-out screencap (без -p), reshape.
         Быстрее, но формат заголовка РАЗНЫЙ на разных
         устройствах (4 / 12 / 16 байт).
      B) PNG в памяти: adb exec-out screencap -p,
         затем cv2.imdecode.
         Медленнее, но работает везде одинаково.
    ТЕКУЩЕЕ РЕШЕНИЕ: вариант B. Вариант A вернуть,
    когда будет замер и понятно, что выигрыш стоит возни.

find_template(screen, template, threshold=0.85)
    Ищет шаблон на ГОТОВОМ скриншоте.
    Возвращает (cx, cy) или None.
    Никакого tap внутри. Никакого imread внутри.
    Никакого exit(). Чистый поиск.

wait_for_template(template, timeout, interval, threshold)
    Цикл поверх find_template.
    Правила: timeout (часы, а не счётчик итераций) +
             interval (пауза) + return None при неудаче.
    Внутри цикла grab_screen() КАЖДУЮ итерацию,
    а не один раз до цикла.

drive(gas_x, gas_y, ...)   [ПЛАН / ЗАГОТОВКА]
    Один цикл: пульс газа + редкая проверка состояния
    (is_crashed) по таймеру last_check.
    НЕ два потока. Одна задача, две вещи по очереди.

is_crashed(screen)
    Принимает готовый screen, возвращает True/False.
    Пока одна строка:
        return find_template(screen, CRASH_TEMPLATE) is not None
    Шаблон крестика вырезан (button_crash.png).

--- КЛЮЧЕВЫЕ РЕШЕНИЯ (не забыть) ---

1. Шаблон читается ОДИН РАЗ.
   cv2.imread НЕ внутри горячего цикла.
   Файл не меняется — читать его на каждой итерации
   бессмысленно.

2. Функция принимает ГОТОВЫЕ данные, а не пути.
   find_template(screen, template) — массивы.
   imread — снаружи, в bot4.py или main.py.
   Не делать "умные" функции, которые принимают
   и строку, и массив. Один тип на входе.

3. Один скриншот — несколько проверок.
   Снимаем экран один раз, ищем на нём разные шаблоны
   (start, crash, pause), не делаем 3 скриншота.

4. Проверка состояния — по таймеру, не каждый цикл.
   Газ: 0.3с. Проверка: 1.0с.
   Две частоты в одном цикле.

5. exit() — только в main.py / bot4.py.
   В библиотеке — return None / False.


--- ИЗВЕСТНЫЕ ГРАБЛИ (по факту столкновения) ---

A) grab_screen через raw screencap ломается на заголовке.
   Ошибка: "cannot reshape array of size N into shape (H,W,4)".
   Причина: размер заголовка не 12 байт, а другой.
   Диагностика: pixels = W*H*4; header = len(raw) - pixels.
   Решение: PNG + imdecode — надёжнее.

B) Типы! find_template ждёт numpy-массив,
   а передали строку ("button_start.png") ->
   AttributeError: 'str' object has no attribute 'shape'.
   Причина: wait_for_template передал строку дальше.
   Решение: imread делать в bot4.py до вызова.

C) Если button_start.png отсутствует или битый,
   cv2.imread вернёт None. Проверять сразу:
       if template is None: print; exit(1)
   Иначе упадёт позже и непонятно где.

D) Окно "SECOND CHANCE" при аварии — идеальный маркер.
   Вырезать шаблон вокруг текста "SECOND CHANCE!"
   (фон под окном полупрозрачный, меняется —
   в шаблон брать МИНИМУМ фона).
   Для проверки — не тапать, а is_crashed(screen) -> bool.


--- ИНСТРУМЕНТ: ЗАМЕР ВРЕМЕНИ ---

Только time.perf_counter().
    t0 = time.perf_counter()
    ... работа ...
    t1 = time.perf_counter()
    print(f"{(t1 - t0) * 1000:.0f} мс")

Правила:
  - Не time.time() — скачет от NTP.
  - Печать — ПОСЛЕ замера, не внутри.
  - В цикле: засекать ДО и ПОСЛЕ цикла, делить на N.
  - Минимум 10 прогонов, лучше 100.
  - Мелкое — в цикле 1000 раз, потом делить.

ГДЕ У НАС УЗКОЕ МЕСТО (подозрение, НЕ измерено):
  - grab_screen: ~100-600 мс в зависимости от варианта.
  - find_template на 1920x1200: ~100-300 мс.
  - tap через adb: ~30-80 мс на вызов.
  Первое, что мерить — grab_screen и find_template.

-f 0x00020000  — это шестнадцатеричный код флага  FLAG_ACTIVITY_REORDER_TO_FRONT . Он говорит системе: найди уже запущенный экземпляр этого приложения в стеке задач и просто перемести его наверх, не перезагружая его жизненный цикл.

    # Запустить сервер заново

import subprocess
import os

AUDIO = os.path.expanduser("~/storage/shared/Music")

def say(text, lang="ru"):
    subprocess.run(["termux-tts-speak", "-l", lang, text])

def play(filename):
    path = os.path.join(AUDIO, filename)
    subprocess.Popen(["termux-media-player", "play", path],
                     stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)

def record(name="rec.wav", sec=5):
    path = os.path.join(AUDIO, name)
    subprocess.run(["termux-microphone-record",
                    "-f", path, "-e", "wav", "-l", str(sec)])
    return path

def stop_all():
    subprocess.run(["termux-microphone-record", "-q"], capture_output=True)
    subprocess.run(["termux-media-player", "stop"], capture_output=True)
    subprocess.run(["pkill", "-f", "play-audio"], capture_output=True)

if __name__ == "__main__":
    say("Начинаю запись")
    rec = record("test.wav", 3)
    say("Запись завершена")
    play("test.wav")

======================================================================
ИНСТРУКЦИЯ ПО СБОРУ КООРДИНАТ КАСАНИЙ ЭКРАНА ЧЕРЕЗ ADB
======================================================================

Данное руководство описывает процесс записи и логирования координат 
нажатий на Android-устройстве с помощью утилиты getevent.

----------------------------------------------------------------------
ШАГ 1: Поиск индекса тачскрина
----------------------------------------------------------------------
Каждое устройство ввода (кнопки, датчики, экран) регистрируется в системе 
под своим файлом eventX. Чтобы найти нужный, выполните команду:

    adb shell getevent -p
.   adb shell getevent -p > getevent_p.txt

В выведенном списке найдите секцию, содержащую строки:
    0035  : value 0, min 0, max ..., fuzz 0, flat 0, resolution 0
    0036  : value 0, min 0, max ..., fuzz 0, flat 0, resolution 0
Или упоминание параметров ABS_MT_POSITION_X и ABS_MT_POSITION_Y.

Посмотрите на заголовок этой секции. Там будет указан путь, например:
    add device 1: /dev/input/event1
    name:     "synaptics_dsx"

Запомните имя вашего файла (в данном примере: /dev/input/event1).

----------------------------------------------------------------------
ШАГ 2: Тестирование сбора данных в консоли
----------------------------------------------------------------------
Чтобы проверить, что индекс выбран верно, запустите чтение в реальном 
времени с флагом текстовых меток (-l) и временных штампов (-t):

    adb shell getevent -tl /dev/input/event1

Попробуйте нажать на экран смартфона. В консоли должны побежать строки. 
Основные интересующие нас параметры:
  * ABS_MT_POSITION_X (код 0035) — координата касания по горизонтали.
  * ABS_MT_POSITION_Y (код 0036) — координата касания по вертикали.

Для остановки потока нажмите комбинацию клавиш Ctrl + C.

----------------------------------------------------------------------
ШАГ 3: Запись координат в текстовый файл
----------------------------------------------------------------------
Чтобы сохранить весь поток нажатий в файл на вашем компьютере для 
последующего анализа или создания макроса, выполните команду:

    adb shell getevent -t /dev/input/event1 > touches_log.txt

Пока команда активна, выполняйте нужные действия на экране телефона. 
Все сырые данные будут записываться в файл touches_log.txt в текущую 
папку, откуда вы запустили терминал. После окончания записи нажмите Ctrl + C.

----------------------------------------------------------------------
ВАЖНОЕ ПРИМЕЧАНИЕ (HEX в DEC)
----------------------------------------------------------------------
По умолчанию getevent выводит координаты в шестнадцатеричном формате (HEX). 
Например, если max значение экрана по X составляет 03ff, то в обычном 
десятичном формате (DEC) это будет 1023 пикселя. 

Если вам потребуется автоматически переводить полученные логи в пиксели 
или сделать из них готовый скрипт для кликов (через adb shell input tap), 
это можно сделать с помощью парсеров на Python.
======================================================================

======================================================================
 ПОЛНОЕ АВТОНОМНОЕ РУКОВОДСТВО ПО GIT: ANDROID (TERMUX) И WINDOWS (CMD)
======================================================================
Этот документ содержит исчерпывающие инструкции для управления кодом
внутри локального репозитория и синхронизации через облако GitHub.

----------------------------------------------------------------------
БЛОК 1: ПЕРВИЧНАЯ ПРОВЕРКА И НАСТРОЙКА ПРОФИЛЯ АВТОРА
----------------------------------------------------------------------
Перед началом работы убедитесь, что Git установлен, и система знает, 
кто подписывает сохранения (коммиты).

1. Проверить, установлен ли Git и узнать его точную версию:
   git --version

2. Посмотреть все текущие настройки профиля:
   git config --list

3. Установить или обновить имя автора и email (если список пуст):
   git config --global user.name "Seal100_tablet"
   git config --global user.email "seal100@yandex.ru"

----------------------------------------------------------------------
БЛОК 2: ИНИЦИАЛИЗАЦИЯ И РЕШЕНИЕ ПРОБЛЕМЫ ДОСТУПА В ANDROID (TERMUX)
----------------------------------------------------------------------
1. Чтобы связать Termux с общей памятью планшета (папкой Download), 
   введите команду и нажмите "Разрешить" на экране:
   termux-setup-storage

2. Перейдите в рабочую папку (например, с ботом):
   cd /storage/emulated/0/Download/bot_android_adb

3. Создать новый локальный репозиторий Git в текущей папке:
   git init
   (Команда создаст скрытую папку .git — «мозг» репозитория).

4. РЕШЕНИЕ ОШИБКИ ПОД Android (fatal: detected dubious ownership):
   Если при вводе команд Git блокирует работу из-за разницы прав в Android,
   внесите папку в список доверенных безопасных директорий:
   git config --global --add safe.directory /storage/emulated/0/Download/bot_android_adb

----------------------------------------------------------------------
БЛОК 3: ИСКЛЮЧЕНИЕ МУСОРА ИЗ ОТСЛЕЖИВАНИЯ (.gitignore)
----------------------------------------------------------------------
Файлы кэша Python (*.pyc, __pycache__/) нужно скрывать от Git.
Для этого создается файл с именем .gitignore.

Пример правильного содержимого .gitignore (скриншоты бота остаются!):
   __pycache__/
   *.pyc

Посмотреть, какие файлы сейчас видит Git (измененные или неотслеживаемые):
   git status

----------------------------------------------------------------------
БЛОК 4: ЕЖЕДНЕВНЫЙ ЦИКЛ НА ЛЮБОМ УСТРОЙСТВЕ (СОХРАНЕНИЕ И ОТПРАВКА)
----------------------------------------------------------------------
Когда вы дописали код или добавили файлы, выполните 4 шага:

1. Проверить статус изменений:
   git status

2. Добавить все файлы (или конкретный файл) в индекс для сохранения:
   git add .                     (добавить всё, точка обязательна)
   git add имя_файла.txt         (добавить только один файл)

3. Зафиксировать изменения локально с текстовым комментарием:
   git commit -m "Ваше описание изменений на русском или английском"

4. Отправить созданные сохранения на сервер GitHub в ветку main:
   git push origin main
   (или просто: git push)

----------------------------------------------------------------------
БЛОК 5: СИНХРОНИЗАЦИЯ: КАК ОБНОВИТЬ КОД НА ВТОРОМ УСТРОЙСТВЕ
----------------------------------------------------------------------
Если вы поработали на планшете и сделали 'git push', то чтобы 
забрать актуальный код на компьютере (или наоборот):

1. Перейдите в папку проекта на устройстве, которое хотите обновить:
   cd путь/к/папке/проекта

2. Скачайте последние обновления из облака одной командой:
   git pull

*Правило:* Всегда делайте 'git pull' перед тем, как начать писать код!

----------------------------------------------------------------------
БЛОК 6: ПЕРВЫЙ ЗАПУСК ПРОЕКТА НА НОВОМ УСТРОЙСТВЕ (КЛОНИРОВАНИЕ)
----------------------------------------------------------------------
Если на компьютере или новом телефоне проекта еще нет, скачайте его.

Скачивание по безопасному протоколу SSH (если перенесен ключ id_ed25519):
   git clone git@github.com:kitanov778898/bot_android_adb.git

Проверить, работает ли SSH-связь устройства с сервером GitHub:
   ssh -T git@github.com

Скачивание по протоколу HTTPS (если нужно авторизоваться через браузер):
   git clone https://github.com

----------------------------------------------------------------------
БЛОК 7: ПОЛЕЗНЫЕ СЛУЖЕБНЫЕ КОМАНДЫ ДЛЯ АВТОНОМНОЙ РАБОТЫ
----------------------------------------------------------------------
* Посмотреть историю всех прошлых сохранений (коммитов) одной строкой:
  git log --oneline

* Посмотреть, какие конкретно строчки кода были изменены прямо сейчас 
  (до того, как вы сделали коммит):
  git diff

* Сбросить все незакоммиченные изменения и вернуть файлы 
  к состоянию последнего сохранения (Внимание: изменения сотрутся!):
  git checkout .

6. КЛЮЧЕВЫЕ НАХОДКИ (не забыть!)
----------------------------------------------------------------
--- Лимит кодека screenrecord ---
1920x1200 НЕ тянет — Encoder failed (err=-38).
Рабочий максимум: 1920x1080 (обрезает до 1728x1080, offset x=96).
Безопасные: 1728x1080, 1600x1000, 1280x720.
Высота > 1080 — кодек отваливается.

--- Скриншот — узкое место ---
adb shell screencap -p = 400–600 мс на цикл (медленно).
Причина: PNG-сжатие + двойная передача через shell.
Решение: adb exec-out screencap БЕЗ -p (raw) + декод в памяти.
Ожидаемое ускорение: 5–10 раз.

--- matchTemplate — суть ---
    result = cv2.matchTemplate(screen, template, cv2.TM_CCOEFF_NORMED)
    _, max_val, _, max_loc = cv2.minMaxLoc(result)
max_val — уверенность (0..1), чем больше — тем лучше.
max_loc — координаты ВЕРХНЕГО ЛЕВОГО угла найденного фрагмента.
Центр = (max_loc[0] + w//2, max_loc[1] + h//2).
Порог: обычно 0.85–0.95. TM_CCOEFF_NORMED — стандарт для игр и UI,
устойчив к изменению яркости, значения от -1 до 1.

--- BGR, а не RGB ---
OpenCV использует порядок Blue, Green, Red:
    Красный = (0, 0, 255)
    Зелёный = (0, 255, 0)

10. ПРАВИЛА, КОТОРЫЕ МЫ ВЫВЕЛИ ПО ХОДУ
----------------------------------------------------------------
- В модуле (библиотеке) НЕ вызывать exit(). Только return.
- exit(1) — для ошибки, exit(0) — успех. Только в main.py.
- Функция делает ОДНО дело. Не «искать + тапать + выходить».
- Имена: snake_case. Функции — глагол в начале (find_, tap_, grab_).
- Параметры функции — маленькими буквами. Константы — БОЛЬШИМИ.
- Если функция может не найти — вернуть None, а не падать.
- В любом цикле ожидания: timeout + interval + return None.
- Если что-то читаем с диска — проверяем на None сразу.
- Докстринг — первая строка в функции, в тройных кавычках.
  Формат: краткое описание + Args/Параметры + Returns.

11. ПСИХОЛОГИЧЕСКИЙ КОНТЕКСТ (важно!)
----------------------------------------------------------------
Это не «мотивашка». Это решения, принятые в ясном уме.
Через полгода они не восстановятся задним числом.

- Не гнаться за «пятиклассником» — это тревожная мысль,
  а не реальность. По коду видно уверенное владение
  subprocess, cv2, numpy, дефолтами, while True.
- Прогресс есть: кодек, OpenCV, matchTemplate — большой путь.
  Ощущение прогресса обманчиво, список пройденного — нет.
- Мозг достраивает понимание во сне и на паузах.
  Застрять и ничего не делать — тоже полезно.
- Работать маленькими шагами, по одной функции за раз.
  Соблазн «переписать всё сразу» убивает проекты чаще,
  чем ошибки в коде.
- Интерес важнее скорости.

ИНСТРУКЦИЯ: ПОДКЛЮЧЕНИЕ К TERMUX ПО SSH ЧЕРЕЗ ADB (USB)
======================================================

1. НА ПЛАНШЕТЕ (В Termux):
   * Задать пароль для пользователя (если не задан): 
     passwd
   * Узнать точное имя своего пользователя: 
     whoami
   * Запустить SSH-сервер: 
     sshd

2. НА КОМПЬЮТЕРЕ (В командной строке Windows - CMD):
   * Построить виртуальный мост (пробросить порт через USB):
     adb forward tcp:8022 tcp:8022
   
   * Обычное подключение по SSH (замените u0_aXXX на имя из пункта 1):
     ssh u0_aXXX@localhost -p 8022

======================================================
3. КАК ПРОВЕРИТЬ СВЯЗЬ (Если что-то не работает):
   * Проверить, активен ли мост в ADB:
     adb forward --list
   * Проверить, слушает ли компьютер порт 8022 (в CMD):
     netstat -ano | findstr 8022
     (В конце строки должно быть написано LISTENING)

======================================================
4. НАСТРОЙКА ВХОДА БЕЗ ПАРОЛЯ (ПО КЛЮЧАМ):
   * Шаг А: Создать ключи на компьютере (нажимать Enter на все вопросы):
     ssh-keygen -t ed25519
   
   * Шаг Б: Скопировать ключ в Termux одной строкой (замените u0_aXXX):
     type %USERPROFILE%\.ssh\id_ed25519.pub | ssh u0_aXXX@localhost -p 8022 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
     (Потребуется ввести пароль в самый последний раз)

   * После этого вход по команде "ssh u0_aXXX@localhost -p 8022" 
     будет происходить мгновенно без ввода пароля!

======================================================
Примечание: Команду "adb forward tcp:8022 tcp:8022" нужно вводить 
на компьютере каждый раз заново после переподключения USB-кабеля.

grab_screen()
    Скриншот -> BGR numpy-массив, без файла на диске.
    ДВА ВАРИАНТА РЕАЛИЗАЦИИ:
      A) raw: adb exec-out screencap (без -p), reshape.
         Быстрее, но формат заголовка РАЗНЫЙ на разных
         устройствах (4 / 12 / 16 байт).
      B) PNG в памяти: adb exec-out screencap -p,
         затем cv2.imdecode.
         Медленнее, но работает везде одинаково.
    ТЕКУЩЕЕ РЕШЕНИЕ: вариант B. Вариант A вернуть,
    когда будет замер и понятно, что выигрыш стоит возни.

find_template(screen, template, threshold=0.85)
    Ищет шаблон на ГОТОВОМ скриншоте.
    Возвращает (cx, cy) или None.
    Никакого tap внутри. Никакого imread внутри.
    Никакого exit(). Чистый поиск.

wait_for_template(template, timeout, interval, threshold)
    Цикл поверх find_template.
    Правила: timeout (часы, а не счётчик итераций) +
             interval (пауза) + return None при неудаче.
    Внутри цикла grab_screen() КАЖДУЮ итерацию,
    а не один раз до цикла.

drive(gas_x, gas_y, ...)   [ПЛАН / ЗАГОТОВКА]
    Один цикл: пульс газа + редкая проверка состояния
    (is_crashed) по таймеру last_check.
    НЕ два потока. Одна задача, две вещи по очереди.

is_crashed(screen)
    Принимает готовый screen, возвращает True/False.
    Пока одна строка:
        return find_template(screen, CRASH_TEMPLATE) is not None
    Шаблон крестика вырезан (button_crash.png).

   find_template(screen, template) — массивы.
   imread — снаружи, в bot4.py или main.py.
   Не делать "умные" функции, которые принимают
   и строку, и массив. Один тип на входе.

3. Один скриншот — несколько проверок.
   Снимаем экран один раз, ищем на нём разные шаблоны
   (start, crash, pause), не делаем 3 скриншота.

4. Проверка состояния — по таймеру, не каждый цикл.
   Газ: 0.3с. Проверка: 1.0с.
   Две частоты в одном цикле.

5. exit() — только в main.py / bot4.py.
   В библиотеке — return None / False.


--- ИЗВЕСТНЫЕ ГРАБЛИ (по факту столкновения) ---

A) grab_screen через raw screencap ломается на заголовке.
   Ошибка: "cannot reshape array of size N into shape (H,W,4)".
   Причина: размер заголовка не 12 байт, а другой.
   Диагностика: pixels = W*H*4; header = len(raw) - pixels.
   Решение: PNG + imdecode — надёжнее.

B) Типы! find_template ждёт numpy-массив,
   а передали строку ("button_start.png") ->
   AttributeError: 'str' object has no attribute 'shape'.
   Причина: wait_for_template передал строку дальше.
   Решение: imread делать в bot4.py до вызова.

C) Если button_start.png отсутствует или битый,
   cv2.imread вернёт None. Проверять сразу:
       if template is None: print; exit(1)
   Иначе упадёт позже и непонятно где.

D) Окно "SECOND CHANCE" при аварии — идеальный маркер.
   Вырезать шаблон вокруг текста "SECOND CHANCE!"
   (фон под окном полупрозрачный, меняется —
   в шаблон брать МИНИМУМ фона).
   Для проверки — не тапать, а is_crashed(screen) -> bool.


--- ИНСТРУМЕНТ: ЗАМЕР ВРЕМЕНИ ---

Только time.perf_counter().
    t0 = time.perf_counter()
    ... работа ...
    t1 = time.perf_counter()
    print(f"{(t1 - t0) * 1000:.0f} мс")

Правила:
  - Не time.time() — скачет от NTP.
  - Печать — ПОСЛЕ замера, не внутри.
  - В цикле: засекать ДО и ПОСЛЕ цикла, делить на N.
  - Минимум 10 прогонов, лучше 100.
  - Мелкое — в цикле 1000 раз, потом делить.

ГДЕ У НАС УЗКОЕ МЕСТО (подозрение, НЕ измерено):
  - grab_screen: ~100-600 мс в зависимости от варианта.
  - find_template на 1920x1200: ~100-300 мс.
  - tap через adb: ~30-80 мс на вызов.
  Первое, что мерить — grab_screen и find_template.

# ИНСТРУКЦИЯ: НАСТРОЙКА SSH В TERMUX

## 1. Первичная настройка (в Termux)
Обновите пакеты, установите OpenSSH и задайте пароль для входа:
```bash
pkg update && pkg upgrade -y
pkg install openssh -y
passwd
```

## 2. Сбор данных для подключения
Узнайте имя вашего пользователя и локальный IP-адрес:
```bash
whoami
```
*(Выведет имя пользователя, например: u0_a123)*

```bash
ifconfig wlan0
```
*(Ищите строку "inet " — там указан локальный IP-адрес, например: 192.168.1.50)*

## 3. Запуск и управление сервером
* **Запустить SSH:** `sshd`
* **Остановить SSH:** `pkill sshd`
* **Проверить, запущен ли:** `logcat | grep sshd` или `netstat -tlpn` (порт 8022)

---

## 4. Способы подключения извне (из Интернета)

### Вариант А: Через виртуальную сеть Tailscale (Самый простой и безопасный)
Не требует белого IP и настройки роутера. Работает через мобильный интернет.
1. Скачайте приложение **Tailscale** из Google Play / F-Droid на телефон.
2. Установите Tailscale на компьютер/устройство, с которого будете подключаться.
3. Войдите в один и тот же аккаунт на обоих устройствах.
4. В приложении Tailscale на телефоне скопируйте выданный IP-адрес (например, `100.x.x.x`).
5. Запустите в Termux команду `sshd`.
6. Подключайтесь с ПК командой:
   ```bash
   ssh [IP_из_Tailscale] -p 8022
   ```

### Вариант Б: Проброс портов на домашнем роутере (Если есть «белый» IP)
1. Зайдите в админку роутера (обычно `192.168.1.1` или `192.168.0.1`).
2. Найдите раздел **Port Forwarding** (Проброс портов / Виртуальные серверы).
3. Создайте правило:
   * **Внешний порт:** Любой свободный (например, `2222` или `8022`)
   * **Внутренний IP:** Локальный IP телефона (из шага 2)
   * **Внутренний порт:** `8022`
   * **Протокол:** TCP
4. Узнайте свой внешний IP (например, на 2ip.ru).
5. Подключайтесь из любой точки мира:
   ```bash
   ssh [Ваш_Внешний_IP] -p [Внешний_порт]
   ```

---

## 5. Шпаргалка для подключения с ПК/другого устройства
Команда для терминала (Linux/macOS/Windows PowerShell):
```bash
ssh [имя_пользователя]@[IP_адрес] -p [порт]
```
Пример для локальной сети:
`ssh u0_a123@192.168.1.50 -p 8022`

Termux: Python-обёртка

```python
import subprocess
import os

AUDIO = os.path.expanduser("~/storage/shared/Music")

def say(text, lang="ru"):
    subprocess.run(["termux-tts-speak", "-l", lang, text])

def play(filename):
    path = os.path.join(AUDIO, filename)
    subprocess.Popen(["termux-media-player", "play", path],
                     stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)

def record(name="rec.wav", sec=5):
    path = os.path.join(AUDIO, name)
    subprocess.run(["termux-microphone-record",
                    "-f", path, "-e", "wav", "-l", str(sec)])
    return path

def stop_all():
    subprocess.run(["termux-microphone-record", "-q"], capture_output=True)
    subprocess.run(["termux-media-player", "stop"], capture_output=True)
    subprocess.run(["pkill", "-f", "play-audio"], capture_output=True)

if __name__ == "__main__":
    say("Начинаю запись")
    rec = record("test.wav", 3)
    say("Запись завершена")
    play("test.wav")
```

# Личная шпаргалка по Git & Termux

Это краткое справочное руководство по командам, конфигурации и работе с ветками, которые мы подробно разобрали на практике. Оно содержит всё необходимое, чтобы быстро сориентироваться в консоли.

---

## 🛠️ Настройки автоматизации Termux (`~/.bashrc`)

Вы можете добавить эти строки в конфигурационный файл вашего терминала, чтобы работать быстрее и удобнее:

* **Автодополнение по нажатию Tab (для команд Git):**
  ```bash
  pkg install bash-completion
  source ~/.bashrc
  ```
* **Короткое сокращение для очистки экрана (`clr` вместо `clear`):**
  ```bash
  alias clr="clear"
  ```
* **Команда для быстрого исправления опечаток с `ualias`:**
  ```bash
  sed -i 's/ualias/alias/g' ~/.bashrc
  ```
* **Обновление конфигурации в текущей сессии:**
  ```bash
  source ~/.bashrc
  ```

## 🗂️ Справочник основных команд Git

| Команда | Что делает на практике / Контекст применения |
| :--- | :--- |
| **`git status`** | **Главный радар.** Показывает текущее состояние проекта: на какой вы ветке, изменены ли файлы, есть ли неотслеживаемые папки. |
| **`git config --global core.quotepath false`** | **Исправление кодировки.** Включает корректное отображение русских букв в названиях файлов вместо цифровых кодов вроде `\320\267...`. |
| **`git diff`** | **Просмотр изменений.** Показывает точные построчные правки в файлах. Зеленый цвет с плюсом `+` — добавленные строки, красный с минусом `-` — удаленные. *Для выхода нажмите английскую клавишу `Q`.* |
| **`git diff "имя_файла.txt"`** | **Точечный просмотр.** Показывает изменения только для одного конкретного файла. Кавычки обязательны, если в имени есть пробелы. |
| **`git restore "имя_файла.txt"`** | **Сброс и отмена.** Полностью отменяет все незакоммиченные правки в файле, возвращая его к состоянию чистого оригинала. |
| **`git branch`** | **Список веток.** Выводит список всех созданных веток проекта. Символ `*` подсвечивает ветку, в которой вы находитесь прямо сейчас. |
| **`git checkout -b имя_ветки`** | **Создание черновика.** Создает новую локальную ветку на телефоне и сразу переключает вас внутрь неё. Сервер об этой ветке пока не знает. |
| **`git switch имя_ветки`** | **Прыжок между ветками.** Позволяет мгновенно переключаться между существующими ветками (например, `git switch main` или `git switch cleanup`). |
| **`git mv "файл.txt" папка/`** | **Умный перенос.** Перемещает файл в другую папку силами Git. Файл сразу остается на контроле у системы и подсвечивается зеленым как `renamed`. |
| **`git commit -m "Сообщение"`** | **Точка восстановления.** Навсегда записывает подготовленные (зеленые) изменения в историю репозитория на устройстве и снабжает их вашим комментарием. |
| **`git push -u origin имя_ветки`** | **Первая выгрузка.** Отправляет новую локальную ветку на GitHub в первый раз и накрепко связывает её с телефоном для последующих обновлений. |
| **`git push`** | **Синхронизация.** Быстро загружает все сделанные вами новые коммиты текущей ветки на удаленный сервер GitHub. |
| **`git merge имя_ветки`** | **Слияние результатов.** Команда вливает изменения из указанной ветки в ту, на которой вы стоите сейчас (например, переносит наведенный порядок в `main`). |

---

## 💡 Полезные напоминания:
1. **Точка входа неизменна:** При переключении веток путь к проекту (`~/.../downloads/bot_android_adb`) не меняется. Git просто переставляет файлы в одной папке как декорации на сцене.
2. **Внимательность к деталям:** Любой лишний перенос строки, пробел или пустая строка — это изменение для Git. Всегда проверяйте себя через `git diff`, чтобы не плодить пустые коммиты.

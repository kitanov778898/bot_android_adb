	# Инструменты взаимодействия с планшетом (Шпаргалка)

## Настройка подключения
Взаимодействие с планшетом происходит с компьютера на базе Windows через стандартную консоль CMD, USB-провод и режим ADB. 

Связь с окружением Termux организуется через двухтерминальную конфигурацию (SSH-туннель) следующими шагами:

1. **Проброс порта через ADB (в CMD на Windows):**
   ```cmd
   adb forward tcp:8022 tcp:8022
   ```

2. **Подключение по SSH (в CMD на Windows):**
   ```cmd
   ssh localhost -p 8022
   ```

## Проверка активной сессии
После успешного подключения по SSH внутри Termux можно проверить список запущенных процессов, чтобы убедиться, что вы находитесь в правильной консоли.

* **Команда:**
  ```bash
  ps
  ```

* **Пример правильного вывода терминала:**
  ```text
    PID TTY          TIME CMD
  30208 pts/1    00:00:00 /data/data/com.termux/files/usr/bin/bash
  26913 pts/1    00:00:00 ps
  ```
  *Где `bash` — это текущая активная командная оболочка Termux, открытая через SSH.*


## Структура двух консолей (Матрёшка)

Для правильного взаимодействия важно различать, с какой именно системой вы работаете в данный момент:

1. 💻 **Первая консоль — Windows CMD (Внешняя)**
   * **Где запущена:** На вашем компьютере.
   * **Как выглядит строка ввода:** Начинается с пути к папке на ПК (например, `C:\Users\79100\Downloads\111>`).
   * **Для чего нужна:** Для управления подключением к планшету. Именно здесь пишутся команды `adb forward` и `ssh localhost`.

2. 📱 **Вторая консоль — Termux Bash через SSH (Внутренняя)**
   * **Где запущена:** Внутри вашего планшета, но отображается на экране ПК после ввода команды `ssh`.
   * **Как выглядит строка ввода:** Начинается со значка тильды и доллара (например, `~/.../bot_android_adb/new $`).
   * **Для чего нужна:** Для управления самим планшетом. Все Linux-команды (`ps`, `nano`, `chmod`), запуск скриптов на Python, а также встроенные команды Android (`dumpsys`) вводятся строго сюда.

## Правило взаимодействия
* Если перед вами `C:\...>`, вы управляете компьютером и можете отдавать команды через ADB.
* Если перед вами `~/... $`, вы находитесь внутри «мозга» планшета (в Termux) и управляете его внутренними файлами и скриптами напрямую.

# ТЕХНИЧЕСКИЙ ПАСПОРТ ПРОЕКТА: АВТОМАНИПУЛЯЦИИ

## 1. АППАРАТНОЕ ОКРУЖЕНИЕ (Данные диагностики Termux)
* **Производитель:** Lenovo
* **Модель устройства:** TB331FC (Xiaoxin Pad)
* **Версия Android:** 13
* **Архитектура процессора:** aarch64 (64-bit)
* **Ограничения:** Нет Root-прав, нет GSM/SIM-карты.

adb devices
adb forward --list

## 2. СХЕМА ВЗАИМОДЕЙСТВИЯ И СЕТЕВАЯ АРХИТЕКТУРА
Связь и управление строятся по трехслойной схеме («Матрёшка в матрёшке»):

* **Слой 1: Компьютер (Windows CMD)** — внешняя оболочка (`C:\Users\...`). 
  Служит для начального проброса портов (`adb forward tcp:8022 tcp:8022`) и входа на планшет через команду: `ssh localhost -p 8022`.

* **Слой 2: Планшет (Termux Bash через SSH)** — промежуточная оболочка Linux (`~/... $`).
  Здесь выполняется автоматизация. Так как на планшете НЕТ root-прав, для симуляции кликов используется обход ограничений через беспроводную отладку Android.

* **Слой 3: Локальный ADB внутри Termux (Скрипт adb.sh)** — ядро управления.
  Внутри Termux запускается скрипт `adb.sh` (Автор: Китанов Виктор, Версия: 1.1.0).
  1. Скрипт открывает меню разработчика Android.
  2. Сканирует локальные порты через `nmap` в диапазоне 30000-45000.
  3. Находит открытый порт беспроводной отладки WLAN (например, 37133).
  4. Выполняет команду: `adb connect localhost:[порт]`.
  
### Результат диагностики Слой 3 (Внутри Termux):
Команда `adb devices` внутри Termux выдает успешное сетевое подключение к самому себе:
`localhost:37133 device`
Это дает Термуксу легальное право выполнять команды кликов (например, `adb shell input ...`) без root-прав.

## 3. РЕЖИМ «СТОРОЖА» (Wake Lock) И ДИАГНОСТИКА ЭКРАНА
Для контроля активности процессора Lenovo используется `termux-wake-lock`. 

### Подтвержденный инструмент проверки экрана (Без ROOT):
Экспериментальным путем найдена точная системная команда для проверки статуса дисплея через локальный ADB (Слой 3):
`adb shell "dumpsys display | grep mScreenState"`

* **Результат при выключенном экране:** `mScreenState=OFF`
* **Результат при включенном экране:** `mScreenState=ON`

Эта команда станет основой для нашего будущего 5-минутного тестового скрипта.


## 3. РЕЖИМ «СТОРОЖА» (Wake Lock) И ЕГО СИСТЕМНЫЙ СТАТУС

### Как гарантированно запустить "сторожа" (В Termux):
`termux-wake-lock`

### Подтвержденный инструмент проверки статуса из adb shell:
`adb shell dumpsys power | grep -E "PARTIAL_WAKE_LOCK.*termux"`

### Успешный результат диагностики:
При активном "стороже" система Android возвращает строку:
`PARTIAL_WAKE_LOCK 'termux:service-wakelock'`
Если вывод пустой — сторож выключен.
